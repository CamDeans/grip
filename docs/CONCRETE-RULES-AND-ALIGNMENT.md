# Concrete Rules and Codebase Alignment

This doc lists all Cursor rules in `.cursor/rules/` and where GRIP's code enforces them. Use it to verify alignment before/after changes.

---

## Mandatory process rule (source of truth and changes)

**We work only from this file and `.cursorrules`.** All GRIP behavior, rules, and alignment are defined and tracked here and in `.cursorrules`. No other doc or rule set overrides these two.

**Before updating either file:** Every change to `docs/CONCRETE-RULES-AND-ALIGNMENT.md` or `.cursorrules` must be **verified and confirmed** (e.g. proposed, then approved) so we stay on track and on the same page. Do not edit these two files without that confirmation.

## StackBlitz preview: no root app when app lives in src/app (rule 24)

**Cause of 404:** Next.js uses the root `app/` folder when it exists. If that root `app/` only has `globals.css` and no `layout.tsx` or `page.tsx`, the App Router has no root layout or home page and returns 404 for `/`.

**Fix:** When the real app lives in `src/app/`, remove the root `app/` directory from the StackBlitz export. In export: delete every file key starting with `app/`; move `app/globals.css` to `src/app/globals.css` first so global styles are preserved. Next.js then uses `src/app` only and the preview loads correctly. Code generation should prefer a single app directory (use `src/app/` and do not create root `app/` when the plan/structure uses src/app).

**Enforcement:** `export-files/route.ts` and `legal-sandbox/export-files/route.ts` both strip root `app/` when `deps.next` and any key starts with `src/app/`.

## Full automation concrete requirements (full-grip-build)

These are the concrete requirements for the mandatory flow; code must align so users do not waste tokens on false or partial results.

1. **Project creation and analysis using all pipeline steps ("all middles")** — On create (with repo) or when opening Overview with linked repo but no analysis, GRIP runs full analysis: repo clone, ideation-based technical prompt, tree-sitter/structured analysis. **Single pipeline:** All analysis flows use the same backend: Overview calls POST `analysis/refresh` (returns 202, triggers `analysis/run`); new-project page fires POST `analysis/refresh` in background; POST `/analyze` (EnhancedChat, ProjectForm) calls `analysisService.analyzeProject` directly with `maxDuration = 120`.
